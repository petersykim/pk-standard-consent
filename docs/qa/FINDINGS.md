| C-001 | pk-standard-consent | D1 Functional (missing control) | S3 | The Consent Log screen's "Erase All" capability (DELETE /admin/log, a full-table wipe) is fully implemented end-to-end on the backend AND the API client (`clearLog()` in `assets/admin/src/api/log.ts:82-84`), but `clearLog()` is imported and called NOWHERE in `ConsentLog.tsx` -- there is no button, no confirm dialog, no UI path to trigger it at all. An admin can only invoke this destructive, whole-table action by hand-crafting a REST call. Per-visitor scoped erase (the GDPR-correct action) DOES have a full UI (`EraseVisitorDialog`), so the gap is specifically the blunt "erase everyone" control, not erasure generally. | open -- needs a product decision, not a pure bugfix (should a destructive whole-log wipe button even exist in the UI, or was the client-side `clearLog()` function left as dead code intentionally when the team standardized on scoped-only erasure for GDPR correctness?) | REST-level wipe already covered by `e2e/qa/consent-admin-log-and-categories.spec.ts` ("DELETE /admin/log wipes the whole table") -- no UI-level spec exists because there is no UI to drive |
| C-002 | pk-standard-consent | Da11y Accessibility | S3 | The shared `@pk/ui` `<Switch>` component (`_shared/ui/src/components/Field.tsx`) accepted an `aria-label` prop at every consent admin call site (8 total: Settings.tsx x4, RegionsTable.tsx x3, CookieScan.tsx x1) but `SwitchProps` never declared it and the component never forwarded it to the underlying `<input>` -- every one of these switches had ZERO accessible name. Confirmed live: `getByLabel()` (which mirrors how a screen reader identifies a control) could not find any of them before the fix. Checked all 8 other plugins in the workspace for the same `<Switch aria-label=...>` pattern -- zero hits, so this is contained to consent, not a workspace-wide design-system bug. | fixed -- `SwitchProps` now declares `"aria-label"?: string`, `Switch` forwards it onto the `<input>`; consent's `assets/dist/admin.js` rebuilt via `pnpm build` to pick up the shared-component change | `e2e/qa/consent-bug-switch-aria-label.spec.ts` |
